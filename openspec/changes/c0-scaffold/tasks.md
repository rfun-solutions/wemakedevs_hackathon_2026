### Rules of engagement (top of `AGENTS.md`, from the initial commit; also pasted into every agent prompt)
1. **Isolation.** Work only in your own worktree: `git worktree add ../wt/<agent> -b <branch> origin/main`. Use `PORT=$KC_PORT`, `VITE_PORT=$KC_VITE_PORT` and `DATABASE_URI=…/kc_<agent>` from the orchestrator's ports file. Never set `DASH0_TOKEN` locally. Set `ANTHROPIC_API_KEY` locally only with the orchestrator's OK.
2. **Branch naming.** `feature/KC-<issue>-<change-id>[-<part>]-pr<k>` (for example `feature/KC-5-d-access-kit-cards-pr3`); `bugfix/` for staged breaks. A new branch per PR, always from `origin/main`. Never branch from another agent's unmerged branch: a squash merge turns that into an add/add conflict. Commit format `feat: [KC-<n>] …`, with the GitHub noreply email.
3. **Rebase policy under the merge queue.** Strict up-to-date is off, so update your branch only when GitHub shows a conflict, the queue ejected your PR, or you need code that is now on `main`. To update: `git fetch origin && git merge origin/main`, re-run your tests, push, `gh pr merge <n> --auto` (no `--squash`; the queue sets the method). Never rebase a pushed branch and never force-push. `git pull --rebase` is allowed only for local, unpushed commits on top of Gitar's commits.
4. **Gitar.** Label each PR `gitar-managed`. After Gitar pushes, run `git pull --rebase` before your next commit. Reject, and report to the orchestrator, any Gitar commit that edits another change's files, weakens a test or a11y rule, or touches `.github/workflows/`.
5. **Shared files.** Insert only under your own `>> <change-id>` marker. Never edit outside the Ownership list of your change and task groups. Never touch dependencies, `package-lock.json`, `tsconfig*`, `playwright.config.ts` or the `vitest` config; touch `vite.config.ts` only with orchestrator approval. Lockfile accident: `git checkout origin/main -- package-lock.json && npm ci`. Tick only your own lines in `tasks.md`. Never run `openspec archive`.
6. **Before you open a PR.** Run `npm run lint && npm test`, the Playwright specs of your change (iPhone 15 + Pixel 7, axe) and `openspec validate <change> --strict`. Push only when ready for review (every push costs about 6 CI jobs). Open PRs only after the orchestrator posts **RULES LIVE**; do not enqueue until **LOOP PROVEN**.
7. **Claiming work.** Your task groups are fixed in your prompt. Claim them with a comment `claimed: groups X` on your GitHub issue and one log line. Do not take another agent's tasks without the orchestrator's assignment.
8. **The running doc.** (Approved by the user 2026-11-08.) Build agents append to RUNNING-LOG.md; the orchestrator syncs the running doc. Append only, never Edit/Write the file: `printf -- '- %s [<agent>] [KC-n] <event>\n' "$(date +%H:%M)" >> RUNNING-LOG.md (outside the repo; absolute path given in your agent prompt)`. Log start, PR opened, merged, blocked and decisions.
9. **Stop and ask the orchestrator; do not improvise** when you need a file outside your ownership or a new dependency; an interface signature differs from the design; `main` is red or the deploy is broken; your PR has been ejected twice; the cluster shows quota or CrashLoop; LLM cost appears; you are 30 min past your time box; or anything involves secrets, the ruleset, repo variables (`FEED_FIXTURE`/`FEED_MODE`), the `kc-chaos` ConfigMap or `KC_DEMO_SEED`.
10. **After every merge:** check with the Radar MCP (sync status, `get_changes`, warning events) and note anything odd in the PR.

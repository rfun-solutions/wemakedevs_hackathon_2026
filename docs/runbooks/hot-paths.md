# Runbook: rules from production (hot-paths)

`scripts/rules-from-prod.mjs` queries Dash0 for route p95 and caption lag p95 and writes
`.gitar/review/hot-paths.md`. Each rule sentence carries its limit, the live p95 and the HH:MM it was
measured, because Gitar quotes rule sentences, not the header.

## Why there are two ways to run it

The org secret `DASH0_TOKEN` is INGEST-ONLY: it cannot query metrics. The scheduled and dispatched workflow
`rules-from-prod` therefore skips cleanly ("Dash0 rejected the token ... nothing written") unless a repo secret
`DASH0_API_TOKEN` with query rights is added. The stage path is the laptop run below, with a full-access
token supplied at run time. Never commit, paste or log the token.

## Laptop path (stage path)

```bash
git switch -c feature/KC-3-rules-from-prod-live origin/main   # from a clean checkout
DASH0_API_TOKEN=<full-access token> node scripts/rules-from-prod.mjs --window 15m --force
git diff .gitar/review/hot-paths.md                            # header names the hot route, e.g. /api/agenda
git add .gitar/review/hot-paths.md
git commit -m "rules: update hot-paths from Dash0 ($(TZ=America/Denver date +%H:%M))"
git push -u origin HEAD && gh pr create --label gitar-managed --title "rules: update hot-paths from Dash0" --body "Generated by scripts/rules-from-prod.mjs"
```

- Keep the PR title starting `rules:`: after the squash merge the `deploy` workflow skips head commits that start with `rules:` (no image is needed).
- Useful flags: `--dry-run` prints the file without writing; `--fixture` writes the fixture numbers (labelled "not production") without any network.
- The script writes only `.gitar/review/hot-paths.md` and refuses any other `--out`. It exits 0 and writes nothing on no token, 401/403, timeout or no series, and says why.

## Workflow path

`gh workflow run rules-from-prod -f window=15m -f force=true`. It commits as the deploy bot straight to `main`
only when a query-capable secret exists; otherwise it logs the skip and exits green.

## Stage use (15:47, after F's 15:45 load)

1. Run the laptop path with `--window 15m --force`; confirm the file header shows `/api/agenda` and the rule is merged to `main`.
2. T-3 min before the slot: open the prepared PR `feature/KC-<n>-agenda-session-counts` (adds one query per session inside the agenda handler loop; label `gitar-managed`; never merged). Gitar reviews in about 1 min.
3. On stage: show the HP-1 line in the rule file (10 s); show Gitar's inline finding opening `Per the review rule "...` and quoting HP-1 with the production p95 (30 s); say "production wrote this rule" (20 s).
4. Fallback: the dress-rehearsal PR tab. Reset: close the PR; the next run rewrites the file.
